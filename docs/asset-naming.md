# Именование ассетов: словарь имён

**Статус:** действующий · **Принят:** 29.09.2026 · **Обновлён:** 04.10.2026 ·
**Основание:** фича `art-organization` (спек и тикеты 01–20, грилл пересмотра 29.09.2026);
префикс `RM_` — решение владельца 04.10.2026 (фича `apv-scenario-tools`, проверка плана 01)
**Проект:** SpiderRig · Unity 6.3 LTS (`6000.3.20f1`) · URP 17.3

Документ отвечает на вопрос **«как назвать файл»**. Куда его положить — в
[`asset-organization.md`](asset-organization.md). Имена в коде — `code-quality.md` §4.2;
префиксы ассетов к коду не применяются.

**Словарь действует на всё собственное, включая UI.** Старые имена — долг: новый файл
называется по словарю сразу, старый — когда его трогают. Вендорские острова и содержимое
`_BlockoutKit` словарю не подчиняются.

### Что было в прежнем регламенте и что решено

| Было (`asset-organization-and-naming.md` §6, 22.09.2026) | Решено на самом деле |
|---|---|
| `PF_<Role>_<Domain>_<Name>` | роль — первый блок: `CHNK_ ACT_ KIT_ PRP_ FX_ UI_`; `PF_` не вводится (§3) |
| `MSH_` | `SM_` статичный меш, `SK_` скелетный |
| `MAT_` | `MT_` материал, `MTV_` вариант |
| `VFX_` на префабе эффекта | `FX_` — префаб эффекта, `VFX_` — только VFX Graph |
| `_Mask` для упакованной карты | буквы каналов в порядке RGBA: `_MAHS`, `_MS` (§4.2) |
| номер сегмента — только в имени сцены | и в имени папки сегмента; в именах файлов и ключах — нет (§6) |
| `PMAT_Spider_SurfaceGrip` | `<Name>` у `PMAT_` — поведение: `PMAT_Spider_NoFriction` |
| `C#` в §6.7 | имена кода — `code-quality.md` §4.2; `UnityEditor` в runtime — §2.4; остальное (стиль без дефекта) не перенесено |

## 1. Грамматика

```text
<PREFIX>_<Domain>_<Name>[_<Variant>][_<Index>][_<Map>].<ext>
```

- английский ASCII, без пробелов и кириллицы;
- смысловые слова в `PascalCase`, `_` разделяет крупные блоки;
- порядковые номера с нулями: `01`, `02`, `10`;
- вариант назван по смыслу, версия в имени не хранится — для этого git.

**Имя самодостаточно.** В Unity ищут глобальным поиском по имени, где путь не виден.
Поэтому имя повторяет домен, даже если папка его уже называет. **Домен — смысловая
принадлежность, а не место хранения**: при обобщении ассета (переезд в `Sets` или `Shared`)
имя не меняется. Ступень общности (`_Common`, `_Shared`) в имя не пишется.

Домены — словом: `Laboratory`, `Route`, `Factory`, `Biosphere`, `Products`, `Interactive`,
`Cutscene`, `UI`. Одно написание на весь проект.

```text
ХОРОШО                                   ПЛОХО
PRP_Factory_MetalHouse_A.prefab          SM_MetalShitHouse_A (1)
TEX_Laboratory_FloorSand_BC.png          Слой 1.png
MT_Water_Stylized.mat                    NewMaterial_Final_v2.mat
```

## 2. Зачем префикс

**Префикс нужен там, где фильтр типа Unity бессилен.** Поиск по имени ищет подстроку в
любом месте имени, а фильтр `t:` разводит типы ассетов. Префикс несёт то, чего фильтр
не различает:

| Что отличить | Фильтр Unity | Префикс |
|---|---|---|
| материал / текстура / префаб / модель / звук | `t:Material`, `t:Texture2D`, `t:Prefab`, `t:Model`, `t:AudioClip` | не нужен сам по себе |
| роль префаба | все `t:Prefab` | **нужен**: `CHNK_ ACT_ KIT_ PRP_ FX_ UI_` |
| вид карты | все `t:Texture2D` | **нужен**: суффикс карты (§4) |
| статичный / подвижный жёсткий / скелетный меш | все `t:Model` | **нужен**: `SM_` / `RM_` / `SK_` |
| материал / вариант | оба `t:Material` | **нужен**: `MT_` / `MTV_` |
| где лежит, кто использует | `glob:`, `ref:` в окне Search | не нужен |

**Внутри одного типа ассета префиксы не должны быть подстрокой друг друга.** `FX_`, `VFX_`,
`SFX_` живут на разных типах — это допустимо. Односимвольные префиксы не вводятся.

## 3. Словарь

| Префикс | Что | Шаблон и пример |
|---|---|---|
| `CHNK_` | чанк-префаб места | `CHNK_<NNN>_<Place>` · `CHNK_004_Factory` |
| `CHR_` | персонаж | `CHR_<Name>` |
| `ACT_` | актор | `ACT_<Domain>_<Name>` |
| `KIT_` | модуль кита | `KIT_<Domain>_<Name>_<Variant>` · `KIT_LevelKit_Ground_A` |
| `PRP_` | проп, статика места | `PRP_<Domain>_<Name>_<Variant>` · `PRP_Factory_MetalHouse_A` |
| `FX_` | префаб эффекта | `FX_<Domain>_<Name>` |
| `UI_` | UI-префаб — **только префаб** | `UI_<Feature>_<Name>` |
| `SM_` / `SK_` | статичный / скелетный меш | `SM_Factory_Pipe_A` |
| `RM_` | подвижный жёсткий меш: анимирован или двигается целиком, без скина. Не `SM_` — импорт `SM_` в `Art/Worlds` включает Contribute GI | `RM_Laboratory_Anima_Wall` |
| `MT_` / `MTV_` | материал / вариант материала | `MT_Laboratory_Floor` · `MTV_Laboratory_Floor_Dirty` |
| `TEX_` | текстура | `TEX_<Domain>_<Name>_<Map>` · `TEX_Factory_Wall_A_N` |
| `RT_` | render texture | `RT_Spider_Glass` |
| `SHD_` / `SHG_` | шейдер / shader graph | `SHD_Weather_SkyProcedural` |
| `.hlsl` | без префикса, по имени семьи | `WeatherFog.hlsl` |
| `ANIM_` / `AC_` / `AOC_` | клип / контроллер / override controller | `ANIM_Flower_Defeat` |
| `AV_` / `MASK_` | avatar / avatar mask | `MASK_Spider_UpperBody` |
| `SFX_` / `AMB_` / `MUS_` | звук / фон / музыка | `SFX_Flower_Pickup` |
| `VFX_` | только VFX Graph | `VFX_Generator_Sparks` |
| `DATA_` | данные игровых систем, которые читает код | `DATA_Weather_Preset_CloudBand` |
| `SVC_` | shader variant collection | |
| `PMAT_` | физматериал | §3.2 |
| `TL_` | таймлайн | `TL_Flower_Pickup` |
| `URP_` / `VP_` / `LS_` | конфигурация рендера | §3.4 |

Префабные варианты знака не получают: Unity показывает их иконкой и заголовком Prefab Mode.
Материалу знак варианта нужен (`MTV_`): в инспекторе объекта материал виден только строкой.

### 3.1 Роль префаба

Роль — **первый блок имени, не папка**: проп, получивший поведение, становится актором
правкой имени, а не переездом файлов.

- **`ACT_`** — у объекта **собственное поведение**: наш скрипт, работа по событиям, память.
  Число мест, где он стоит, ни при чём.
- **`PRP_`** — статика без нашего скрипта. Живой декор (мигание, `Animator` без геймплея,
  эмбиент-`AudioSource`) — `PRP_` или `FX_`, не актор.
- **`KIT_`** — повторяемый модуль строительного набора со своим pivot.
- **`CHNK_`** — уникальное место. `CHNK_000_<Name>` — база сегмента (`asset-organization.md` §2.1).
- Статика мест в обёртках «FBX + коллайдер без скриптов» — `PRP_`.

**Вложенный визуал актора** — FBX и материалы без логики внутри префаба актора —
`PF_<Domain>_<Name>Visual`: `PF_Energy_PotionVisual`. Это единственное место, где остаётся
`PF_`: у визуала нет собственной роли, он часть актора.

### 3.2 `PMAT_`

`PMAT_<Domain>_<Name>`, где `<Name>` — **физическое поведение прилагательным** в `PascalCase`:
`NoFriction`, `Bouncy`, `HighGrip`. Место установки в имя не пишется: `PMAT_Spider_NoFriction`.

### 3.3 `DATA_` — не конфигурация рендера

`DATA_` закреплён за данными, которые читает наш код. URP Asset, Renderer Data, Volume Profile,
Lighting Settings — конфигурация движка: их не читает код, их подставляют в Quality Settings,
`Volume` и вкладку Lighting. Общий префикс склеил бы сущности, которые меняют по разным поводам.

### 3.4 Конфигурация рендера

**Ось — уровень качества, а не платформа** (платформа одна, PC):

```text
URP_Low.asset · URP_Medium.asset · URP_High.asset    URP Asset на Quality Level
URP_Main_Renderer.asset                              Renderer Data, один на все уровни
VP_<Scope>_<Name>                                    VP_Main_World, VP_Sandbox_Weather
VP_Default                                           профиль по умолчанию URP
LS_<Scope>_<Name>                                    Lighting Settings
```

Отдельный облегчённый renderer заводится, только когда доказано, что на Low нужно выключить
проходы. Ассеты, создаваемые движком (`UniversalRenderPipelineGlobalSettings`, `LightingData`),
не переименовываются (`asset-organization.md` §6.4).

## 4. Текстуры

### 4.1 Суффикс карты

Суффикс говорит, **как текстуру читать**:

| Карта | Суффикс |
|---|---|
| Base Color / Albedo | `_BC` |
| Normal | `_N` |
| Metallic | `_M` |
| Ambient Occlusion | `_AO` |
| Smoothness / Roughness | `_S` / `_R` |
| Height | `_H` |
| Emission | `_E` |
| Opacity | `_O` |

Не смешивать `_Albedo`, `_BaseColor`, `_Diffuse` для одного значения.

### 4.2 Упакованные карты

Упакованная карта называется **буквами каналов в порядке RGBA**:

- `_MAHS` — `ENV_Lit`: R metallic · G AO · B height · A smoothness;
- `_MS` — URP Lit: R metallic · A smoothness, G и B не заняты.

Обобщённый `_Mask` запрещён: в проекте две упаковки, и одно слово на обе их путает.
При расхождении с шейдером прав шейдер (`ENV_LitInput.hlsl`).

### 4.3 UI и флипбуки

- Текстура UI — `TEX_UI_<Feature>_<Name>`. `UI_` без `TEX_` — только префаб.
- **Спрайт — без суффикса карты**: `TEX_UI_Frame_BluredBlue_A`. У спрайта нет «вида карты».
- **Флипбук — суффикс сетки кадров**: `TEX_UI_KittyPaw_Love_6x5`, `TEX_FX_Sparks_8x8`. По нему
  режут кадры.
- Текстура под UI-спрайт импортируется в `Sprite Mode: Single`, если её не режут. В режиме
  `Multiple` без нарезки Unity не создаёт ни одного спрайта, ссылка молча резолвится в
  `null`, а `Image` рисует сплошной прямоугольник цветом `Color` (поймано 08.09.2026 на полосе
  здоровья паука). Проверка: раскрыть текстуру в Project — нет дочернего спрайта, значит ни
  одна ссылка не работает.

## 5. Исключения

### 5.1 Шрифты

Файлы шрифта (`.ttf`, `.otf`) и лицензия сохраняют имена, как пришли:
`RobotoMono-VariableFont_wght.ttf`, `OFL.txt`. SDF-ассеты TextMeshPro — по словарю.

### 5.2 Модуль с собственным префиксом

Шейдер модуля, чьё имя — префикс семьи (`ENV_Lit.shader` и его `ENV_Lit*.hlsl`), сохраняет
имя модуля: `ENV_` — имя системы, а не префикс типа.

### 5.3 Текстуры, которые FBX ищет по имени

У FBX со **встроенными** материалами (`materialImportMode` не 0, материалы не вынесены)
Unity при импорте ищет текстуры по именам, записанным внутри FBX. Переименуешь или унесёшь
такую текстуру — при следующем реимпорте материал её потеряет. Ссылки по GUID при этом
не видно, аудит показывает текстуру как попавшую в билд без прямой ссылки.

**Перед переименованием текстуры рядом с FBX** — открыть `.fbx.meta`:
- материал из FBX переназначен на внешний `.mat` в `externalObjects` — поиск по имени для
  него ничего не решает, переименовывать можно;
- материал встроенный и берёт эту текстуру — не переименовывать, пока модель не переведена
  на внешние материалы. Примеры: `TEX_Tower_AO.jpg` у `SM_Cutscene_Intro_Tower.fbx`,
  17 карт продуктов `Actors/Products`.

Имя самого FBX на этот поиск не влияет. После переименования FBX — открыть префабы-потребители
и убедиться, что Missing нет.

## 6. Сцены и номер сегмента

| Роль | Формат | Пример |
|---|---|---|
| загрузчик, резидентный слой | точное имя | `Bootstrap.unity`, `Gameplay.unity` |
| владелец атмосферы мира | `World_<Мир>` | `World_Common.unity` |
| сегмент | `Seg_<NN>_<Name>` | `Seg_01_Base.unity` |
| песочница | `Sandbox_<Feature>` | `Sandbox_Weather.unity` |
| узкий тест | `Test_<System>_<Case>` | `Test_Streaming_UnloadReload.unity` |

`SCN_` не вводится: имя сцены подчиняется её архитектурной роли (`scene-regulations.md`).
Песочницы и тесты лежат в `Scenes/Sandbox/` — имя не защищает от попадания в билд, защищает
папка и валидатор.

**Номер сегмента живёт в трёх местах: имя сцены, её `SegmentDefinition` и папка арта
сегмента** (`Art/Worlds/Tower/Seg_01/`), одной ширины. **Не в именах файлов и не в ключах**
(`GameDatas`, `LevelDataKey`). Перенумерация этажа — переименование сцены и папки через Unity,
GUID переживает; ключ или имя файла с номером пришлось бы искать по всему проекту.

Номер чанка (`CHNK_004`) — не номер сегмента, он в имени файла разрешён.

## 7. Запрещённые суффиксы

`Final`, `Latest`, `New`, `Old`, `Copy`, `(1)`, `(2)`, случайные даты, инициалы автора,
`Test` у файла в билде, `.001` из DCC как единственное объяснение различия, `v2`, если обе
версии не реальные варианты. Допустимы осмысленные варианты: `_LOD0`, `_Mobile`, `_A` / `_B`.

## 8. Как проверить

`GD Tools/Build Content Audit`, раздел 7 отчёта «Фактический словарь» — считает префиксы
и суффиксы по файлам категории A. Отклонение — не ошибка сборки, а список к правке при
касании. Числа в регламент не переносятся: они меняются вместе с игрой.
