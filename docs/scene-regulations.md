# Регламент ведения сцен

**Статус:** действующий · **Принят:** 31.08.2026 · **Основание:** грилл 31.08.2026,
`.scratch/additive-scenes-vertical/GRILL-LEDGER-2026-08-31.md`

Это главный документ по сценам. Если открыл проект впервые — читай его целиком,
он короткий. Всё остальное по сценам — обоснования и история.

| Документ | Роль |
|---|---|
| **этот** | действующие правила: что где лежит и почему |
| `scene-architecture.md` | **исторический разбор.** Часть решений оттуда пересмотрена, см. его шапку |
| `asset-organization-and-naming.md` | папки и имена файлов; по сценам подчиняется этому документу |

Правила ниже проверяемы машиной там, где написано «валидатор». Всё, что держится
на памяти исполнителя, через полгода не соблюдается — поэтому таких правил здесь
стараемся не иметь.

## 1. Мир — единица загрузки

```
                        МИР = ОДИН АССЕТ КАТАЛОГА
                     Assets/Settings/World/DATA_World_*.asset

   ┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
   │  DATA_World_     │   │  DATA_World_     │   │  DATA_World_     │
   │      Tower       │   │      Room_*      │   │     Sandbox      │
   ├──────────────────┤   ├──────────────────┤   ├──────────────────┤
   │ сегментов: много │   │ сегментов: 1–2   │   │ сегментов: 1     │
   │ паук: да         │   │ паук: да         │   │ паук: да         │
   │ свой набор APV   │   │ свой набор APV   │   │ свой набор APV   │
   └──────────────────┘   └──────────────────┘   └──────────────────┘
        боевой столб         комната-уровень       серые боксы, метрики
                             вне столба            НИКОГДА В БИЛД
```

Столб, комната и песочница — **один и тот же примитив**. Комната это вырожденный
столб с одним сегментом; песочница — то же самое, но вне боевого каталога.
Третьей сущности в проекте нет и заводить её не нужно.

**Смена мира** = перетащить другой ассет каталога в поле `WorldCatalog`
на `Assets/Resources/StaticData/GameData/GameData.asset`. Одно перетаскивание,
кода нет. Выпадашка миров в окне `GD Tools/Scenes` появится, когда миров станет
трое, а не раньше.

**Переход между мирами — всегда полная выгрузка под шторку.** Это не оптимизация,
а условие работоспособности: живым может быть только один набор запекания APV, и
сцена из чужого набора **молча игнорируется** — без ошибки и без предупреждения
(`ProbeReferenceVolume.AddPendingSceneLoading`, строки 1406–1411, комментарий в
исходнике: «This should not throw an error, but it's not supported»).
Комната, загруженная поверх живого столба, останется без непрямого света, и никто
об этом не узнает.

## 2. Резидентный слой

```
╔════════════════════════════════════════════════════════════════════════╗
║  Bootstrap.unity      всегда индекс 0 в Build Settings                  ║
║  Gameplay.unity       SceneContext · паук · камера · HUD · сервисы      ║
║  ExitGameLoop.unity   служебная                                        ║
║  ────────────────────────────────────────────────────────────────────  ║
║  World_<Мир>.unity    ★ ВЛАДЕЛЕЦ RenderSettings, грузится Single,      ║
║                         становится АКТИВНОЙ сценой                     ║
╚════════════════════════════════════════════════════════════════════════╝
```

**У каждого мира ровно одна сцена — владелец `RenderSettings`.** Небо, ambient,
туман, отражения и ссылка на Lighting Settings берутся из неё и больше ниоткуда.

Для столба это `World_Tower.unity` (сейчас называется `World_Common`) — там живёт
погодный риг, солнце и луна. Комната с небом получает свою. **Закрытый интерьер
без окон получает свою тоже** — без skybox, с ambient плоским цветом. Причина:
«нет `RenderSettings`» не бывает. Без явного владельца активной станет случайная
сцена, и небо приедет от порядка загрузки, то есть от маршрута игрока.

> **ЗАПРЕТ.** Ни одна резидентная сцена и ни одна сцена-владелец атмосферы
> не содержит Probe Volume. Никогда. Иначе она пришпилит набор запекания своего
> мира, и следующий мир свой набор не подхватит — молча.
> *Валидатор.*

## 3. Сегменты столба

```
 ВЫСОТА                                             СОСТОЯНИЕ
 ─────────────────────────────────────────────────────────────────────
 Seg_05  ████████████████████████████████   загружен · Live активен
 Seg_04  ████████████████████████████████   загружен · Live активен
 Seg_03  ██████████ ПАУК ███████████████    загружен · Live активен
 Seg_02  ████████████████████████████████   загружен · Live активен
 Seg_01  ████████████████████████████████   загружен · Live активен
 ─────────────────────────────────────────────────────────────────────
         ВСЁ ГРУЗИТСЯ НА СТАРТЕ. ВЫГРУЗКИ НЕТ. ПРЕДЗАГРУЗКИ ПО ПРИБЛИЖЕНИЮ НЕТ.
```

**Почему грузим всё сразу.** Игрок обязан видеть столб снизу вверх — это правило
геймдизайна, не пожелание. Сегмент, который ещё не загружен, не «далеко» — его
не существует. Значит предзагрузка по приближению и требование видимости
взаимоисключающи, и лишняя здесь предзагрузка.

Вниз всё бесплатно: выгрузки нет, падение сквозь десятки этажей летит по уже
загруженному, во время падения не грузится ничего.

**Отказ этой схемы — растущее время загрузки, видное цифрой в логе**
(`[SegmentDirector] '<сцена>' loaded in NNN ms`). Это выбрано сознательно:
такой отказ виден заранее в профайлере, а не у игрока на чужом железе.

**`SegmentBounds` — загрузочная полоса, а не габарит контента.** Авторское число,
монотонно растущее: «с какой высоты сегмент обязан быть в памяти». Геометрия торчит
за полосу сколько угодно, швы между сегментами условные, bounding box'ы пересекаются —
это законно и никого не волнует. Нулевой счётчик `STRADDLES` в Split Report целью
не ставится.

**Активация.** `Live`-ветки включаются **один раз, после инъекции и построения мира**,
сразу во всех сегментах. Логики по высоте нет. Деактивации нет.

**Нумерация.** Пока сегмент один — `Seg_01_Base`. Схема с зазором под вставку слоя
между этажами выбирается при появлении второго. Отложить дёшево, потому что guid
живёт в `.meta` и переименование сцены его не рвёт — **при условии**, что номер
сегмента не появляется нигде, кроме имени файла сцены и её `SegmentDefinition`.
Ни в именах префабов, ни в папках, ни в ключах `GameDatas`.

## 4. Дерево сцены сегмента

```
Seg_01_Base.unity
│
├─ World/            ★ всегда включён — всё по МЕСТУ В МИРЕ
│  ├─ Laboratory/       чанк-префабы и уникальная геометрия лаборатории
│  ├─ Bridge/
│  ├─ Biosphere/
│  ├─ Terrain/          террейн, внешняя оболочка, держащая силуэт
│  └─ _Blockout/        серые боксы; группа удаляется целиком, когда приедет художка
│
├─ Lighting/         ★ всегда включён — сегментное, не принадлежащее месту
│  ├─ объёмы проб APV        ◄ НИКОГДА не внутри префаба
│  ├─ Volume сегмента
│  └─ заполняющий свет полосы
│
├─ Contract/         ★ всегда включён
│  ├─ SegmentBounds
│  ├─ SegmentInjector        ◄ ОБЯЗАН быть вне Live, иначе не проснётся
│  ├─ SpiderSpawnPointMarker · FlowerPointMarker
│  └─ CheckPointMarker · BatteryPointMarker · EnergyPointMarker · ...
│
└─ Live/             ★ ВЫКЛЮЧЕН в сохранённой сцене  ◄ метка SegmentLiveRoot
   ├─ AUD_Segment_Wind       эмбиент высоты на весь сегмент
   ├─ FX Zone - *            погодные зоны сегмента
   └─ TRG_Camera_*           зоны следящей камеры на несколько чанков
```

**Группировка по месту, а не по типу.** Место совпадает с единицей работы: ты
работаешь над лабораторией, а не над «всеми коллайдерами».

| ежедневная операция | по типу | по месту |
|---|---|---|
| «покажи всё про лабораторию» | обойти пять веток | одна ветка |
| «выключи мост, проверю без него» | выделять куски в трёх ветках | один клик |
| «отдать биосферу второму человеку» | невозможно | один префаб |

Группировка по типу (`Geometry/`, `Colliders/`, `Props/`) — это группировка по
**дисциплине**, та же ошибка, что раскол `Scene_StaticMesh` / `Scene_Light` на
уровне сцен, только этажом ниже.

Рамки из дефисов в именах корней (`------GEOMETRY-----!`) — легаси-приём, нужный
только когда групп нет. С настоящими группами не используется.

> **У группировочных объектов трансформ строго единичный** — position 0,0,0,
> rotation 0,0,0, scale 1,1,1. Неединичный масштаб на группе искажает детей
> и **ломает нормали коллайдеров**, по которым паук ставит ноги.
> *Валидатор.*

**Корневой `Live` в сцене должен быть почти пустым.** Почти всё живое лежит внутри
чанков и акторов (раздел 5). Если он раздувается — значит что-то, что должно было
стать актором, положили россыпью.

## 5. Дерево чанк-префаба

```
CHN_Laboratory                          ← чанк-префаб
│
├─ StaticMesh/                          100% статика, Contribute GI ВКЛ
│  ├─ SM_Lab_Walls
│  ├─ SM_Lab_Floor
│  └─ SM_Lab_Pipes
│
├─ Actors/                              всё с поведением — ВЛОЖЕННЫЕ префабы
│  │
│  ├─ PF_Actor_Door_A
│  │  └─ SM_Door                        коллайдер работает ВСЕГДА
│  │                                    Contribute GI ВЫКЛ
│  │                                    Animator выключен, автостарт снят
│  │
│  ├─ PF_Actor_WallBreach
│  │  ├─ SM_Wall_Intact                 коллайдер ВКЛ, Contribute GI ВЫКЛ
│  │  ├─ SM_Wall_Broken                 выключена — владеет СКРИПТ, не активация
│  │  └─ SM_Debris_*                    выключены — владеет СКРИПТ
│  │
│  └─ PF_Actor_Siren
│     ├─ SM_Siren_Body                  корпус статичен: Contribute GI ВКЛ
│     └─ Live/  ◄ метка                 Light + AudioSource + Animator, ВЫКЛЮЧЕН
│
└─ Live/  ◄ метка                       не принадлежащее ни одному актору
   ├─ AUD_Lab_Ambient                   эмбиент помещения
   └─ TRG_Lab_Entry                     триггер-зона входа
```

**Актор остаётся одним объектом.** Сирена не разрезана между корнями — она вложенный
префаб, и раздел живёт внутри неё, уровнем ниже. Открыл её в prefab mode — работаешь
целиком.

**Метка живой ветки рекурсивна.** Она может быть на любой глубине: в сцене, в чанке,
внутри вложенного актора. Активация сегмента включает все метки разом. Именно поэтому
правило «ровно два корня» отменено: оно верно для сцены, неверно для префаба, и
валидатор, считающий корни, врал бы.

**Выключенные обломки — не `Live`.** Их состоянием владеет скрипт актора, а не
активация сегмента. Валидатор смотрит только на помеченные ветки. Разница
принципиальная: `Live` про гонку загрузки, выключенные обломки про игровое состояние.

## 6. Что попадает в `Live`, а что нет

**Критерий:**

> **`Live`** — всё, что при загрузке сцены может запуститься само и наделать дел
> до того, как мир построен, а зависимости внедрены.
> **Не `Live`** — всё, обо что паук может удариться или за что зацепиться,
> и всё, что только описывает состояние рендера.

| объект | где | почему |
|---|---|---|
| стена, пол, уступ | статика | паук цепляется |
| дверь, мост, ворота | статика, поведение гасится покомпонентно | коллайдер обязан работать при падении |
| корпус сирены, корпус монитора | статика | это меш, за него цепляются |
| свет и звук сирены | **Live** | заведутся сами при загрузке |
| партиклы пара | **Live** | заведутся сами |
| триггер-зона, вызывающая код | **Live** | требует паука и внедрённых сервисов |
| `Volume` постпроцессинга, зона тумана | **статика** | ничего не запускает; в `Live` дал бы тихий визуальный дефект при сбое активации |
| погодная зона | **Live** сцены | сегментная, не принадлежит месту |
| обломки, появляющиеся по эвенту | ни то, ни другое | владеет скрипт актора |

> **Триггер, который вызывает код — `Live`. Триггер, который только описывает
> объём для рендера — статика.**

**Проверки валидатора:**

1. каждая ветка с меткой `SegmentLiveRoot` сохранена **выключенной** — иначе ошибка сборки;
2. под меткой нет ни одного `Collider` с `isTrigger == false`;
3. в статике нет `AudioSource.playOnAwake` и `ParticleSystem.playOnAwake`;
4. `Contribute GI` не расходится с назначением группы;
5. `SegmentInjector` лежит вне любой помеченной ветки.

## 7. Свет

### 7.1 Где что живёт

| источник | где лежит | почему |
|---|---|---|
| солнце, луна, небо | сцена-владелец атмосферы мира | один владелец на мир, разъехаться не может |
| заполняющий свет полосы | `Lighting/` сцены сегмента | принадлежит сегменту, не месту |
| **объёмы проб APV** | `Lighting/` сцены сегмента | **никогда в префабе:** чанк ×6 дал бы шесть объёмов, а плотность и границы бейка стали бы случайными |
| лампа интерьера, всегда горит | **внутри чанка**, статическая часть | принадлежит месту |
| мигалка, экран монитора, свет по эвенту | **внутри актора**, его `Live`-ветка | принадлежит актору, гасится вместе с ним |

Тот же принцип, что у звука: **сегментное — в `Lighting/` сцены, принадлежащее
месту — в чанке, принадлежащее актору — в акторе.**

### 7.2 Режим источника — и главная ловушка

```
                    может ли этот свет ВЫКЛЮЧИТЬСЯ в игре?
                                   │
                 ┌─────────────────┴─────────────────┐
                НЕТ                                  ДА
                 │                                    │
      нужна ли чёткая тень / блик?              ★ Realtime ONLY
         │                    │                   в запекании
        ДА                   НЕТ                  НЕ УЧАСТВУЕТ
         │                    │
      Mixed                 Baked
   прямое реалтайм,      всё через пробы,
   непрямое в пробы      нулевая цена в кадре
```

> **★ ЛОВУШКА, из-за которой правило существует.** Непрямое от `Baked` и `Mixed`
> источника **заморожено в пробах**. Выключил в игре лампу — комната осталась
> освещённой лампой, которой нет. Чинится только перезапеканием.
> Это тот же класс дефекта, что запекание закрытой двери.

**То же самое относится к эмиссивным материалам.** Экран монитора, который можно
выключить, обязан иметь в материале `Global Illumination: None`. Иначе его свечение
уедет в пробы и останется там после выключения.

**Подвижная геометрия в запекании не участвует никогда** — дверь, ворота, мост,
разрушаемая стена. Комната печётся так, будто дверь открыта, а стена уже взорвана.
Это ломается в том состоянии, где игрок проводит меньше времени, и потому выбрано
именно так; обратный выбор ломается навсегда после катсцены.

### 7.3 Участие в запекании — это флаг, а не папка

```csharp
// ProbeVolumeGIContributor.cs:37 — единственный критерий
internal static bool ContributesGI(GameObject go) =>
    (GameObjectUtility.GetStaticEditorFlags(go) & StaticEditorFlags.ContributeGI) != 0;
```

Участие в бейке APV определяется **одной галочкой `Contribute GI` на объекте**.
Не иерархией, не слоем, не компонентом. Сбор идёт по всему загруженному
(`GIContributors.Find(ContributorFilter.All)`).

Следствия:

- **папка не может быть источником правды о бейке.** Объект в папке «статика»
  с выключенным флагом — папка врёт;
- **`Contribute GI` на родителе не наследуется детьми.** Unity спрашивает
  «применить к детям?» и проставляет каждому отдельно;
- **флаг сериализуется в префаб.** Поставил в чанке один раз — приехал во все
  шесть инстансов. Именно поэтому потребность в папке «вся статика» исчезает,
  как только контент уезжает в чанки;
- проверка «что попадает в бейк» — **валидатор и вид сцены**, а не структура папок.

## 8. Звук

### 8.1 Пять слоёв

| слой | что | где живёт | 2D/3D | владелец |
|---|---|---|---|---|
| **Музыка** | тема, состояние, катсцена | резидентный `Gameplay`, сервис | 2D | сервис, **не сцена** |
| **Эмбиент мира** | ветер высоты, гул столба | `Live/` сцены сегмента | 3D | сегмент |
| **Эмбиент места** | гул лаборатории, капель | `Live/` чанк-префаба | 3D | чанк |
| **Звук актора** | сирена, пар, дверь, взрыв | `Live`-ветка актор-префаба | 3D | актор |
| **Разовый звук** | шаг, удар, подбор | **нигде в сцене** — пул | 3D | код |

### 8.2 Правила

**1. Ни одного `playOnAwake` вне помеченной живой ветки.** Со столбом, который
грузится целиком на старте, `AudioSource` в статике заведётся под шторкой — сразу
на всех сорока этажах. *Валидатор.*

**2. 2D-звук в сегменте запрещён. 2D — только резидентный слой.** 2D-луп не затухает
с расстоянием: эмбиент сорокового этажа будет слышен на дне одинаково громко.

**3. У каждого 3D-источника конечный `maxDistance`, соразмерный месту.**

```
ProjectSettings/AudioManager.asset
  m_RealVoiceCount: 32        ← одновременно звучащих
  m_VirtualVoiceCount: 512    ← отслеживаемых
```

Сотни эмбиент-луп загруженного столба конкурируют за 32 реальных голоса. Далёкие
обязаны уходить в virtual **сами, по расстоянию** — приоритеты, расставленные руками,
не поддерживаются и разъезжаются на третьем этаже.

**4. Музыка не принадлежит сегменту.** Сегмент может *попросить* смену темы, но
`AudioSource` с музыкой в его сцене — ошибка: при загрузке всего столба заиграют
все треки сразу. Механизм запроса (маркер, зона или сервис по Y паука) выбирается
тогда, когда музыка появится.

**5. Разовые звуки не живут в сцене** — сервис `Pool`.

**6. Звук актора принадлежит актору, а не месту.** В `Live/` чанка лежит только то,
что не принадлежит ни одному актору. Правило одно на все виды поведения — свет,
FX, звук.

## 9. Запекание — что уже решено

Полный регламент по запеканию, пробам отражений и настройкам материалов под них —
**отдельная работа, отдельный грилл.** Здесь только то, что уже принято и влияет
на авторинг.

- **Лайтмап нет вовсе.** Непрямое целиком на пробах APV, прямое и тени — реалтайм.
  Причина: запечённая лайтмапа привязана к экземпляру рендерера и хранится в сцене
  оверрайдом на инстансе — это делает переиспользуемый чанк дорогим.
- **Один набор запекания на мир.** Живым может быть только один — ограничение
  движка, не выбор.
- **Сцена атмосферы обязана быть открыта в момент запекания** — солнце живёт в ней.
- **Сценарии APV отложены.** Порядок проверки: бейк → **записать объём данных проб**
  → включить sky occlusion, перезапечь, прогнать пресеты погоды глазами → и только
  при провале возвращаться к сценариям. Обоснование и цифры —
  в `GRILL-LEDGER-2026-08-31.md`.
- **Запекание не начинается, пока не наведён порядок в сценах-сегментах и в системе
  аддитивных сцен.**
- **Финальный бейк — один человек, одна машина, та же, с которой уходит билд.**
  Запечённые данные лежат одним блобом на весь набор, поэтому любое запекание
  перезаписывает общие бинарные файлы, и двое получают неразрешимый конфликт.

## 10. Запреты одним списком

| запрет | последствие нарушения |
|---|---|
| Probe Volume в резидентной сцене или сцене атмосферы | следующий мир молча без непрямого света |
| Probe Volume внутри префаба | ×N объёмов, случайные границы и плотность бейка |
| запечённый или смешанный свет там, где его можно выключить | комната освещена лампой, которой нет |
| эмиссия с `Global Illumination: Baked` на выключаемом экране | то же самое |
| `playOnAwake` вне живой ветки | все сирены столба заводятся под шторкой |
| 2D-звук в сегменте | эмбиент верхнего этажа слышен на дне |
| музыка в сцене сегмента | все треки играют одновременно |
| неединичный масштаб на группировочном объекте | искажение детей, сломанные нормали коллайдеров |
| не-триггерный коллайдер под живой веткой | паук проваливается сквозь неактивированное |
| `SegmentInjector` внутри живой ветки | весь сегмент без внедрённых зависимостей |
| межсегментная ссылка в сцене | `null` в билде — Unity не сериализует межсценовые ссылки |
| сцена песочницы в боевом каталоге | отладка в билде |
| номер сегмента в имени префаба, папки или ключа `GameDatas` | переименование этажа тянет за собой всё |
| группировка сцены по типу вместо места | ежедневная навигация ломается, отдать кусок человеку нельзя |

## 11. Ограничения движка — цифрами

| ограничение | число | откуда |
|---|---|---|
| потолок высоты столба | **~5–10 км** | `float`: на Y=10 000 шаг ≈1.2 мм, на 100 000 ≈12 мм. Паук ставит ноги по нормали рейкаст-хита |
| одновременно звучащих источников | **32** | `AudioManager.m_RealVoiceCount` |
| отслеживаемых источников | **512** | `AudioManager.m_VirtualVoiceCount` |
| живых наборов запекания APV | **1** | `ProbeReferenceVolume`; сцена из чужого набора игнорируется молча |
| стриминг ячеек APV | **выключен** | `URP_High.asset`, `m_SupportProbeVolumeGPUStreaming: 0` — весь мир обязан поместиться в пул целиком |
| бюджет пула проб | **1024 (Medium)** | `URP_High.asset`, `m_ProbeVolumeMemoryBudget` |
| глубина иерархии | техническая — нет | ограничение человеческое: глубже 5–6 уровней больно перетаскивать |
| батчинг и иерархия | не связаны | static batching и GPU instancing группируют по мешу и материалу, не по родителю |
