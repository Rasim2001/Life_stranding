# Этап: прозрачность и переключение аддитивных сцен

**Статус:** ✅ реализовано и проверено · **Создан:** 26.07.2026 · **Завершён:** 26.07.2026
**Тип:** редакторный тулинг, Editor-only · **Рантайм не изменяется**

## Реализация

Все шаги (0–3) выполнены. Единственный файл инструмента:
[`Assets/Editor/ProjectScenesWindow.cs`](../Assets/Editor/ProjectScenesWindow.cs) ·
пункт меню **`SpiderRig/Scenes`**.

Помимо самого плана, по итогам ревью пользователем добавлены доработки читаемости
(вне первоначального текста шагов, но в рамках той же границы `Assets/Editor/`):

- UI переведён на английский (соответствует стилю существующих редакторных скриптов,
  ср. кнопку «Collect» в `GameDataEditor.cs`);
- строки таблицы сгруппированы: **Utility scenes** → **Logic scenes (candidate Main)** →
  **Content scenes (candidate Additive)**, с разделителем-полосой между группами;
- `Bootstrap` и `ExitGameLoop` помечены как **служебные сцены** (короткий текст
  «Utility Scene» + тултип с причиной) — назначать их основной/аддитивной технически
  не крашит, но даёт пустой уровень (`Bootstrap`: голый `SceneContext` без
  `SceneInstaller`) или ломает цепочку выхода (`ExitGameLoop`, хардкожена в
  `ExitGameLoopState.cs:10`). Guard добавлен и в валидацию (`SetAsMain`/`AddToAdditive`),
  не только в UI;
- у кнопок «Play» / «Play This Scene» / «Open Set» / «Reset Start Scene» под подписью
  кнопки — серым текстом имя сцены(-ен), на которые они реально повлияют (была
  проблема нечитаемости в исходной свёрстке в одну строку);
- тултипы на всех кнопках (включая построчные) — краткая справка для новичков.

## Контекст

Сегодня взаимодействие с аддитивными сценами устроено так: чтобы сменить загружаемый
уровень, нужно открыть `GameData.asset` и вписать строки руками. Ни подсказок, ни проверок.
Понять из редактора, какая сцена несёт логику, а какая — только геометрию, невозможно
без чтения кода.

Цена этого уже видна в самом ассете:

- `LoadScene = Scene_StaticMesh` и **та же сцена** в `AdditiveScenes` — Unity загрузит
  вторую копию всей геометрии поверх первой;
- `Scene_StaticMesh` не содержит `SceneContext`, поэтому `SceneInstaller` и `BuildLevelState`
  не отрабатывают — паук не спавнится, игра фактически не собирается;
- в `GameDatas` есть ключ `Bootstrap` — след нажатия «Collect» при активной сцене
  `Bootstrap`, где маркеров нет. Пустая запись-мусор.

**Цель этапа:** дать прозрачность (что где лежит и что загрузится) и переключение наборов
сцен в один клик, не трогая рантайм и не начиная миграцию архитектуры.

**Чего этап сознательно не делает:** не переименовывает сцены, не вводит `SegmentDefinition`
и каталог, не чинит `Collect`, не меняет ни строки в рантайм-коде.

## Шаг 0. Починить текущий конфиг ✅

Прямо в инспекторе `GameData`, без кода:

```
LoadScene:       SCN_LevelDesingDraft     (сцена с SceneContext и контентом)
AdditiveScenes:  [Scene_StaticMesh]       (геометрия)
```

Удалить из `Game Datas` ключ `Bootstrap`.

Это известная рабочая пара — та, из которой собирался последний работоспособный билд.

**Проверка:** Play из `Assets/Scenes/Bootstrap.unity` — паук появляется, уровень собран,
консоль без ошибок.

## Шаг 1. Окно «Сцены проекта» — только чтение ✅

Новое окно редактора, пункт меню уровня `SpiderRig/Scenes` (в реализации — английское
название меню и всего UI, см. «Реализация» выше).

Таблица по всем сценам проекта (`Assets/Scenes/**`, без сцен сторонних пакетов):

| Колонка | Источник данных |
|---|---|
| Имя и путь | `AssetDatabase.FindAssets("t:Scene")` |
| Роль | наличие `SceneContext` → «логика» / «контент» |
| Маркеры | количество маркеров каждого типа |
| Запись в `GameDatas` | есть ли ключ по имени сцены, сколько точек внутри |
| Build Settings | включена / выключена / отсутствует |
| Объектов | приблизительный размер сцены |
| Текущая роль в конфиге | «основная» / «аддитивная» / «—» |

**Как определять содержимое сцены, не открывая её.** Открывать каждую сцену дорого
и меняет состояние редактора. Вместо этого — текстовый разбор `.unity` (сцены хранятся
как YAML, `m_SerializationMode: 2` в проекте включён): искать GUID нужных скриптов.
GUID брать не хардкодом, а через `AssetDatabase.AssetPathToGUID` по пути скрипта —
тогда перенос скрипта не сломает инструмент. Результат кэшировать, обновлять по кнопке.

**Проверка:** окно показывает, что `SCN_LevelDesingDraft` — с логикой, `Scene_StaticMesh` —
без; виден мусорный ключ `Bootstrap`; видно, какие сцены в Build Settings.

**Ценность шага сама по себе:** это ответ на вопрос «где основная сцена, а где
подгружаемая геометрия» — без переименований и без риска.

## Шаг 2. Переключение наборов сцен ✅

Кнопки в строке таблицы:

- **«Сделать основной»** — записывает `LoadScene`;
- **«Добавить в аддитивные» / «Убрать»** — правит `AdditiveScenes`;
- **«Открыть набор»** — `EditorSceneManager.OpenScene` для основной,
  затем `OpenSceneMode.Additive` для остальных.

**Валидация перед записью — три отказа, все из реальных поломок:**

1. основная сцена **без `SceneContext`** → отказ с объяснением: `SceneInstaller`
   не отработает, паук не появится;
2. **одна и та же сцена** в основной и в аддитивных → отказ: Unity загрузит вторую копию;
3. для основной **нет записи в `GameDatas`** → предупреждение: рантайм упадёт
   с `KeyNotFoundException` в `GameFactory`.

Запись через `EditorUtility.SetDirty` + `AssetDatabase.SaveAssets`.

**Проверка:** набор переключается без открытия `GameData`; попытка воспроизвести обе
текущие поломки блокируется инструментом с внятным сообщением.

## Шаг 3. Play из любой сцены ✅

Кнопки в окне (в реализации — с подписью цели серым текстом под каждой):

- **«Play»** — `EditorSceneManager.playModeStartScene` = `Bootstrap.unity`, вход в Play;
- **«Play This Scene»** — записывает **открытую** сцену как `LoadScene` (через ту же
  валидацию, что и «Set as Main»), затем то же самое;
- **«Open Set»** — открывает текущий сконфигурированный набор в редакторе без входа в Play.

Вторая кнопка закрывает то, чего сейчас нет вовсе: открыл сцену, нажал — играешь именно её,
через полную цепочку загрузки. Всё делается в редакторе, рантайм не трогается.

Отдельная кнопка **«Reset Start Scene»** — вернуть обычное поведение Unity
(`playModeStartScene = null`).

**Проверка:** Play из произвольно открытой сцены поднимает `Bootstrap` → машина состояний →
загрузка набора; паук появляется в выбранной сцене.

## Не входит в этап

| Что | Почему |
|---|---|
| **Переименование сцен** | отдельная атомарная задача: имя активной сцены сейчас несёт три роли (`scene-architecture.md`, 1.5), требуется одновременно править строки в `GameData`, ключи `GameDatas` и Build Settings. Матрица рисков помечает это как критическое до config seam |
| `SegmentDefinition`, `TowerCatalog`, стриминг | это миграция архитектуры, не тюнинг взаимодействия |
| Починка `Collect` | отдельная боль (ключ по активной сцене, `FindObjectsOfType` по всем загруженным сценам) — отдельная задача |
| Любые правки рантайм-кода | граница этапа |
